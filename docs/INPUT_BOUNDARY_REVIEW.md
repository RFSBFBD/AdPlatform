Older Meta readers cast missing/malformed spend, impressions and clicks into zero; malformed optional reach/frequency could coerce or truncate. Discovery supplied USD/UTC and an active status when absent. Hierarchy supplied ACTIVE when status was absent and coerced malformed daily/lifetime budgets through float casts. These defects affect imported observations and derived values/scenarios, not only conversion totals. No claim is made that any specific live response had malformed fields. Do not treat older imported Meta numbers or their real-budget recommendations as verified.

New Meta normalization leaves absent required operands null, so shared metric batch validation refuses rather than replacing old rows with synthetic zeros. Explicit numeric0 stays0. Present malformed/bool/nonfinite/negative values reject, fractional impression/click/reach counts reject, and supported exact-count/storage bounds are enforced. Decimal input strings are bounded decimal notation, not scientific notation or whitespace-coerced text. Optional reach/frequency preserve absent null, reject malformed present values, and are not made additive. Selected purchase values use the same parser. These local limits can conservatively reject valid provider formats; fixtures are not live format validation.

Discovery currency requires an explicit three-uppercase-letter code and timezone requires a known IANA identifier; invalid/missing values become null and existing account connection refuses missing values. This is syntax validation, not an ISO currency registry or currency-unit verification. No currency/timezone is inferred. Node/account identifier conflicts reject. Explicit provider fields carry metadata_source.version=meta-discovery-explicit-1, retained by the existing connection flow. A previously connected account can contain valid-looking old defaults. New metric definitions therefore record whether exact current account fields agree with that explicit discovery evidence; only matching evidence gets the explicit marker. No new sync automatically upgrades an old account's evidence. No reconnect/resync is performed by this work.

The analytical guard now requires strict-meta-operands-1 and explicit account-metadata source as well as exact pixel-purchase keys and consistent definitions. Conversion-only meta-pixel-purchase-1 from the delivered replacement no longer passes this later boundary. This does not authenticate advertiser sales, verify attribution windows, prove full inventory or validate every other provider. No old metric/account/archive is edited or resealed. Typed lead imports remain independent of generic purchase outcomes and retain their separate source limits.

Hierarchy IDs and selected creative/audience IDs are type/length/character checked before string conversion. Daily insight date must parse exactly, fall in the requested range, and have an equal date_stop when present. This prevents pooled multi-day data being stored as one day. Hierarchy paging now uses the same explicit malformed-next rejection as report/discovery. Missing hierarchy status becomes UNKNOWN. Malformed budget numbers reject before the existing /100 mapping. The /100 mapping itself is not newly verified for every currency and must not be treated as authoritative budget guidance. Missing ad creative_type can still use the preexisting generic IMAGE field in the shared engine, so that legacy display field is not canonical creative evidence.
