## Estimands, not assumptions about people

Reported spend and impression/click events can be added across structurally valid nonoverlapping report rows. They are not unique reach/people. Provider-attributed outcome counts/value can be described as that provider's reported events/value when contracts match; this does not promise unique purchases, disjoint people, incremental effect or actual sales. Cross-account overlap alone is not a reason to reject every additive estimand. Unknown account-configured conversion definitions can still differ, and remain separated by their contract scope.

Different providers' outcome/value fields are not currently a supported joint business objective. Matching declaration text does not prove equal event meaning, attribution windows, counting, date basis, value basis or deduplication. Current code has no validated mechanism to establish that equivalence, so it refuses cross-provider joint outcome/value pooling. That is a current capability limit, not a theorem that arithmetic sums are impossible. Currency conversion changes units, not event meaning or attribution.

## Affected paths

- Overview keeps parsed/account-validated spend, impression/click-event totals and delivery ratios. Joint outcome count/value/CPA/ROAS become null with a reason when contracts are incompatible/missing. Currency-breakdown and timeline outcome fields are withheld too; provider breakdowns validate their own source groups. Existing legacy numeric/account transition failures still return their prior refusal, rather than approving old spend.
- KPI groups remain separate provider/currency results. Structural/numeric checks run first; only incompatible group's outcome KPIs are unavailable, with delivery KPIs retained. This endpoint does not return a pooled outcome total.
- Campaign lists validate account groups separately, because a list is not a joint total. Details, scope-based forecast/diagnostic/anomaly/entity reports and existing export routes retain conservative definition guards. Some analytical paths still withhold an entire report instead of producing metric-specific partial output; they do not invent zeros.
- Assumed/fitted platform OR, generic entity outcome objectives and archived decision paths reuse the semantic gate. Typed lead counts keep their separate source definition and do not certify generic purchase semantics; their spend/account checks remain required.
- Unsafe archives preserve stored rows/checksums. Show/list/replay/explanation/comparison/report paths withhold decisions through existing guards. No resealing or repair occurs.

## Explicit portfolio limitation

The existing platform portfolio optimizer requires at least two provider channels. Those generic provider outcomes do not have a verified joint business meaning, so that current route now abstains. It is not completed cross-platform budget capability. Supported same-source entity optimization and pure numerical solvers remain separately tested. Adding a different common first-party outcome source or an explicit defensible surrogate objective would be a separate scoped design, not a silent fallback here.
