# Meta report and discovery pagination correction

Later development after the verified local-test replacement0efe3d3. That delivered artifact remains unchanged and does not contain this correction. No automatic resync, historical repair, source upload or deployment occurs.

Meta insight reports previously stopped with a warning at100pages and returned accumulated metrics as if the fetch succeeded. Discovery next links were not bounded or restricted to the same edge. These are separate from the nested hierarchy path fixed earlier. This correction rejects a report at its page limit rather than returning the partial metric batch. Discovery also rejects at its limit rather than returning a partial account roster.

Both paths now validate each requested page URL against HTTPS graph.facebook.com and the exact configured-version/account insight edge or me/adaccounts discovery edge. Userinfo, explicit port and fragment are forbidden. Every visited URL is tracked; repeated URLs reject before another request. Empty data plus next continues. A page ends only with an absent paging descriptor or absent next field. Present malformed paging, empty/non-string/null next, malformed data envelope, HTTP failure, duplicate discovered account IDs or repeated campaign/day insight keys rejects. Both paths allow at most100requests per fetch. A report's first page and subsequent pages remain in raw evidence only when the full fetch returns; thrown partial raw fetches are not persisted by the current sync engine. A failed later report page cannot write the first page's metrics or advance last_synced_at. Previously saved metrics are not deleted or relabeled.

Pagination rules were grounded in the inspected official cursor reference: https://developers.facebook.com/docs/graph-api/results/ . An empty page can have next, absence of next ends traversal. This is not evidence of live access, current configured API lifecycle, permissions, complete inventory or correct attribution windows.

Limits remain: pages are not an atomic provider snapshot. Mutating report populations or invalidated cursors can cause gaps that local checks cannot detect. Different valid cursor strings might represent the same page; duplicate entity/date checks catch exact repeated insight keys but are not proof of total completeness. Transport redirect following is disabled for paginated reads; redirect responses without valid data fail instead of forwarding the request. Exact-path validation may reject legitimate provider path/version variations rather than quietly broadening the bearer destination. Caps are engineering limits, not a provider completeness certificate. Account defaults for missing currency/timezone, raw numeric mapping and cross-provider contracts are unchanged by this block and require separate grounding. Meta metric-definition, omission and attribution caveats in META_CORRECTED_REPLACEMENT.md still apply. No production or real-budget approval is implied.
