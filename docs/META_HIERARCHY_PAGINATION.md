# Meta hierarchy traversal

Canonical creative and audience observations depend on the ads/ad sets actually fetched. The campaign endpoint's nested expansions have their own paging state. The adapter now traverses adsets and ads next links before returning a normalized hierarchy. An empty data page with next is not the end. All fetched page envelopes are retained in the hierarchy raw payload. Campaign metadata contains the combined ad-set data, not the original nested cursors.

The official reference inspected 23 November 2026 explains cursor pagination, absence of next as termination, and empty pages that still have next: https://developers.facebook.com/docs/graph-api/results/ . The requested fields are unchanged. This is not live permission, configured-version or account validation.

Next URLs are accepted only for HTTPS graph.facebook.com and the exact configured-version/current-parent edge path. Credentials, ports and fragments are rejected. The bearer is not forwarded to another host or another parent edge. No server-returned URL is executed as code. Cycles, duplicate IDs per edge, malformed envelopes, HTTP errors, campaign/edge caps or global hierarchy request cap throw instead of returning truncated success. Campaign pages and each nested edge allow at most100 pages; the hierarchy permits at most1000 new page requests. A sync that fails while fetching hierarchy does not receive a partial normalized hierarchy to save. Adapter-level raw partial results on a thrown fetch are not persisted by the existing sync engine.

Limits remain: paging is not an atomic provider snapshot, mutations during traversal can cause gaps or duplicates (duplicates reject but undetected gaps remain possible). Missing expansions stay unknown, not a claim the parent has no children. This does not repair earlier syncs, delete unseen records, establish historically effective targeting or attribute metrics to creatives/audiences. Other provider inventory pagination contracts and Meta discovery/insight traversal are outside this change. Metadata/raw payloads can still include provider next URLs, as before. No live account or request was used, no authorization/version was changed, no campaign was mutated. Frozen source packages remain unchanged.
